# Cofa Prompt Playbook

Cofa 과제에서 Codex에 단계별로 전달할 범용 Markdown 프롬프트다. 공개 저장소에는 빈 템플릿만 보관한다. 실제 과제 내용, 코드, 데이터, 대화, 로그, 상태 문서와 결과물은 응시 환경 내부에서만 다룬다.

처음 사용하는 경우 [시작 가이드](start.md)를 따라 진행한다.

## 시작 전 확인

응시 화면의 최신 안내와 과제별 규정이 우선이다. 2026-11-04 응시 안내는 과제가 허용하는 공개 자료를 Cofa 내부에서 Git Clone으로 가져올 수 있다고 설명한다. 이 저장소를 참고 자료로 쓸 수 있는지와 접근 가능 여부는 사전 체험에서 확인한다. 불명확하면 Cofa Helper나 운영 안내를 확인한다. 외부 전송과 Git Push는 금지된다. 과제 종료 후 서술형은 AI와 복사·붙여넣기 없이 직접 작성한다.

## 1. 터미널에서 저장소 가져오기

Cofa 웹 IDE에서 터미널을 열고 셸에 아래 두 줄을 입력한다. 파일 탐색기에서 과제 루트의 `README.md`를 먼저 열어 과제별 제한을 확인한다.

```sh
pwd
ls -a
```

과제 루트에 있고 공개 자료 사용과 이 위치에 참고 폴더를 만드는 것이 허용된 경우에만 아래 명령을 실행한다. 시험에서 참고 자료 위치를 따로 지정하면 그 위치를 사용하고 이후 프롬프트의 경로를 바꾼다. 공식 제출 범위에서 참고 폴더를 제외할 수 있는지도 먼저 확인한다.

```sh
git clone https://github.com/wlxoqkdl/cofa-prompt-playbook.git cofa-prompt-playbook
```

폴더가 이미 있으면 덮어쓰거나 지우지 말고 내용과 출처를 확인한다. 인증을 요구하거나 접근이 차단되면 개인 계정·토큰·우회 접속을 사용하지 않는다. Clone 없이 작업할 수 있으면 응시 환경 안에서 원본 README를 기준으로 진행한다. URL 전체를 외울 필요는 없다. 계정명과 저장소 이름 `wlxoqkdl/cofa-prompt-playbook`으로 위 주소를 구성할 수 있다.

Codex에게 복제를 맡기려면 시험 루트에서 `codex`를 실행하고 아래 지시를 입력한다. 직접 복제했다면 이 지시는 건너뛴다.

```text
과제 규정에서 공개 자료 반입과 이 위치에 참고 폴더를 생성하는 것이 허용된 것을 확인했다. 현재 위치와 과제 루트를 확인하고, 루트에서 대상 경로가 이미 존재하는지 확인해 줘. 기존 경로가 없다면 git clone https://github.com/wlxoqkdl/cofa-prompt-playbook.git cofa-prompt-playbook 한 번만 실행해 줘. 기존 파일은 건드리지 말고, 실패하거나 인증을 요구하면 멈추고 이유만 알려 줘. Git Push와 시험 자료 외부 전송은 금지한다.
```

## 2. 첫 Codex 지시

시험 루트에 머문 채 셸에서 `codex`를 실행한다. 신뢰 확인이 뜨면 시험 작업 폴더가 맞는지 확인한다. Codex 입력창에서 `/status`로 모델과 권한을 확인하고, `/model`에서 제공되는 Sol 6.1과 Medium을 선택한다. 메뉴에 없으면 시험 환경에서 허용된 설정을 사용한다. 프롬프트 문장에 모델 이름을 적어도 설정이 바뀌지는 않는다. [OpenAI CLI 명령 안내](https://learn.chatgpt.com/docs/developer-commands?surface=cli)

아래 지시문은 **Codex 입력창**에 붙여넣거나 직접 입력한다.

```text
현재 작업 폴더가 시험 프로젝트 루트인지 확인해 줘. 시험 루트 README.md를 과제의 원본으로 먼저 읽고, cofa-prompt-playbook/RULES.md, cofa-prompt-playbook/README.md, cofa-prompt-playbook/prompts/01_discovery.md 순서로 읽어 줘. 과제 안내를 우선 적용하고 지금은 01 탐색만 해 줘. 시험 루트 README.md는 항상 읽기 전용이다. 이번 단계는 파일 생성·수정·삭제, 설치, 네트워크 요청 없이 진행해 줘. 시험 자료 외부 전송과 Git Push는 금지한다. 필수 요구사항, 제출 조건, 기존 구조, 불확실한 점, 업무 담당자에게 물을 질문을 알려 주고 멈춰 줘.
```

참고 파일 없이 시작할 때는 다음처럼 직접 입력한다.

```text
시험 루트 README.md를 읽기 전용으로 분석해 줘. 파일 변경·설치·네트워크 요청 없이 필수 기능, 제출 조건, 기존 구조, 업무 담당자에게 물을 질문을 알려 주고 멈춰 줘. 시험 자료 외부 전송과 Git Push는 금지한다.
```

## 3. 한 단계씩 진행하기

모든 Markdown을 한꺼번에 붙여넣을 필요는 없다. 다음 단계마다 Codex에 “`cofa-prompt-playbook/RULES.md`와 아래 단계 파일을 읽고 해당 단계만 진행해 줘”라고 요청한다. 직접 붙여넣는 경우에는 공통 규칙과 해당 단계만 전달한다.

| 순서 | 파일 | 실행 시점 |
| --- | --- | --- |
| 01 | [탐색](prompts/01_discovery.md) | 원본 README와 기존 구조를 읽고, 제공되면 업무 담당자에게 질문 |
| 02 | [계획](prompts/02_planning.md) | 인터뷰 요약을 반영해 우선순위·검증 기준·변경 범위를 제안 |
| 03 | [상태 관리](prompts/03_project_status.md) | 계획과 상태 파일 생성 경로를 승인한 후 기록 |
| 04 | [구현](prompts/04_implementation.md) | 승인한 작업 하나씩 구현하고 검증 |
| 05 | [디버깅](prompts/05_debugging.md) | 막힐 때만 사용. 재현과 원인 분석 후 수정 승인 |
| 06 | [검증](prompts/06_validation.md) | 별도 세션에서 확인. 결함은 구현 세션에 돌려보내고 재검증 |
| 07 | [인계](prompts/07_handoff.md) | 세션을 바꾸거나 제출 직전 상태와 남은 일을 정리 |

## 터미널 세 개 운영

| 터미널 | 역할 |
| --- | --- |
| 1. 구현 | 시험 루트에서 Codex 실행. 탐색·계획·구현과 승인된 파일 변경 및 상태 문서 갱신을 담당 |
| 2. 실행 | 일반 셸. 과제에서 정한 서버와 로컬 검증 명령 실행. 서버가 필요한 경우 터미널을 열어 두고 Cofa 미리보기에서 실제 포트 확인 |
| 3. 검증 | 별도 Codex 세션. 원본 README와 실제 결과를 대조하고 근거를 보고. 소스·상태 문서는 수정하지 않음 |

Cofa 터미널의 `+`로 탭을 연다. 서버 미리보기가 필요한 과제라면 가이드에 따라 `0.0.0.0` 바인딩과 실제 포트를 확인하고 Cofa 내부 미리보기만 사용한다. 검증하는 동안 1번의 파일 변경을 잠시 멈춘다. 여러 탭이 어렵다면 같은 역할을 차례로 수행한다.

## 추론 수준 선택

- **Sol Medium**으로 탐색, 승인된 단위 구현, 재현이 쉬운 수정, 상태 문서 정리를 진행한다.
- **Sol High**로 인터뷰와 원본 요구사항을 종합해 설계하고, 복잡한 오류를 진단하거나 독립 검증을 수행한다.
- **Sol XHigh**는 High까지 시도했지만 필수 기능을 막는 복합 원인이 남고 시간 여유가 있을 때만 사용한다. 재현 절차, 확인한 근거와 제외한 가설을 함께 전달하고 해결 뒤 Medium으로 돌아온다.

3터미널과 추론 수준 배분은 작업 전략이다. 모델과 도구는 시험 환경이 실제로 제공하고 허용하는 범위에서만 사용한다.

## 제출

시험 루트 README를 보존하고 공식 제출 대상·경로·형식·저장 상태를 확인한다. 참고용 복제 폴더나 Git 메타데이터, 임시 출력물이 공식 제출 범위에 섞였는지 작업 폴더와 제출 안내를 대조해 확인한다. 제출 미리보기에는 일부 파일만 표시되므로 목록만으로 제외 여부를 판단하지 않는다. 제출은 응시자가 Cofa의 공식 절차로만 진행하며 외부 GitHub나 개인 저장소로 전송하지 않는다.
