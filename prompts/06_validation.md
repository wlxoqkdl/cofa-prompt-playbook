# 06 독립 검증

**권장 모델 및 추론 수준** · Sol 6.1 / High

`RULES.md`를 적용한다. 별도 세션에서 시험 루트 README와 과제 안내를 먼저 읽고, 구현 내용과 제출 대상 파일을 직접 대조해 줘. 검증이 끝날 때까지 구현 세션의 편집을 잠시 멈춘다.

보고 첫머리에 통과한 것, 실패한 것, 아직 확인하지 못한 것을 쉬운 말로 나눠 줘. 제출 전에 고쳐야 할 문제가 있으면 사용자에게 어떤 영향이 있는지 한 문장으로 알려 줘. 자세한 확인 근거는 그 아래에 적어 줘.

- 요구사항별로 확인 절차, 파일 또는 실행 근거, 결과를 `통과 / 실패 / 미검증`으로 보고해 줘. 핵심 흐름과 대표 실패 입력을 우선 확인해 줘.
- 상태 문서가 있으면 `완료` 표시를 독립 검증 결과와 대조하고, `실패` 또는 `미검증`인데 완료로 표시된 항목을 결함으로 보고해 줘.
- 부수 효과가 없는 허용된 검사를 실행해 줘. 파일을 쓰는 빌드·테스트나 서버 실행이 필요하면 명령과 영향을 보고하고 승인받은 뒤 실행 담당 터미널에서 결과를 확인해 줘.
- 시작 상태와 비교해 시험 루트 README, 보호 파일, 승인 범위를 점검해 줘. Git 프로젝트라면 `git status --short`와 `git diff HEAD -- README.md`를 확인하고, 시작 시 이미 있던 변경은 별도로 구분해 줘. Git이나 시작 기준이 없으면 확인 가능한 근거와 한계를 명시해 줘.
- 제출 파일의 이름·위치·형식·저장 상태와 불필요한 참고 폴더·임시 파일 포함 여부를 확인해 줘. 결함은 중요도, 재현 절차, 기대 결과와 함께 1번 터미널에 전달할 형태로 정리해 줘.

검증 세션에서 소스, 설정, 상태 문서를 편집하거나 제출하지 않는다. 수정 후에는 같은 절차로 재검증한다.
